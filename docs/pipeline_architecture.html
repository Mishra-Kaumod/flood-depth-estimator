End-to-end request flow

Upload → guardrails → async queue/sync path → staged model inference → calibrated response → metrics

Execution paths

Async default: POST /predict enqueues Celery job and returns job_id; client polls GET /predict/<job_id>.
Sync override: POST /predict?sync=1 runs inline via _predict_single().
Fallback: if queue backend is unavailable, API falls back to sync mode with mode=sync_fallback.

Runtime dependency chain

  • app.py → calls scripts.tasks.infer_flood_depth (async) or _predict_single (sync).
  • _predict_single → get_segformer_yolo_depthv2_pipeline().predict().
  • SegformerYoloDepthV2Pipeline → WaterRegionDetector + ReferenceDepthEstimator + optional YOLO + optional Gemini.
  • Gemini path → guarded by run_with_retry, CircuitBreaker, ApiBudgetTracker.
  • Queue path → src.pipeline.execute_event and DLQ routing on permanent failure.

Operational dependency chain

  • Readiness evaluator and manifest scripts feed CI quality gates.
  • Deploy workflow depends on quality gate and shadow canary before ECS rollout.
  • /metrics exposes counters/histograms/gauges consumed by Prometheus/Grafana.
  • Config values in config/config.yaml drive retries, budgets, and seasonal alert thresholds.
  • docs/pipeline_architecture.html is the single canonical architecture dashboard.

Leadership workflow (high-level)

Business-level lifecycle from image intake to operational action.

Phase What happens Why it matters Success signal
1. Ingest & protect Image uploads are validated, rate-limited, and accepted via API. Prevents abuse and bad input from affecting service quality. Low 4xx abuse noise, stable intake latency
2. Process at scale Requests are queued and processed asynchronously with sync fallback safety. Maintains responsiveness during monsoon spikes. Healthy queue depth and completion rates
3. Estimate flood depth Five-stage pipeline computes water extent, depth, severity, and action cues. Produces actionable flood intelligence, not just raw model output. Consistent depth + severity outputs
4. Degrade safely If AI services fail or confidence is weak, system falls back to classical logic. Avoids hard outages and limits unsafe predictions. Fallback used without service interruption
5. Observe & alert Health/metrics expose latency, failures, Gemini fallback, suppression rates. Enables operational control and fast incident response. SLOs inside thresholds
6. Release with gates Model readiness and canary checks must pass before deploy. Prevents low-quality or risky models from reaching production. Gate-pass deploys only
